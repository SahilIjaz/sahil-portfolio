Design review · sahil-portfolio · July 2026

From dev template to client magnet

A section-by-section redesign spec for sahilijaz's portfolio — what to keep, what to cut, and the layout that sells the work instead of the effects.

Verdict: strong raw material, wrong packaging. The portfolio has real shipped products — including two apps live on the App Store and Play Store — but presents them behind a 3D loading screen, gradient text, fake screenshot placeholders, and a category literally named “Simple Projects.” Clients hire outcomes and credibility; right now the site sells animation. The redesign below keeps your stack and content, and changes what the visitor sees first.

01

Audit — keep vs. cut

What the current site gets right, and what is costing you clients.

Keep

  • Real, deployed projects with live URLs 11 projects, 2 in mobile app stores — this is your strongest asset.
  • Modern stack: Next.js 16, React 19, Tailwind 4 Credible to technical buyers; keep it in the footer, not the headline.
  • Working contact form with API route (Resend) Most portfolios fake this. Yours works.
  • Clean component structure & TypeScript throughout Good engineering hygiene — it shows when clients open the repo.

Cut

  • 3D loading screen, animated cursor, 3D section dividers, skill orbs Reads as a 2021 template; slows first paint on the phones clients browse on.
  • Blue→purple→pink gradient text everywhere The single most recognizable “AI/template portfolio” tell.
  • Fake abstract “previews” instead of real screenshots You have live products — show them. Screenshots convert; shapes don't.
  • Skill percentage bars (Node.js 95%) Meaningless to clients, junior signal to engineers.
  • “Simple Projects” category label You are literally telling visitors your work is simple.
  • “API key suspended — demo may be unavailable” note Never ship a broken demo. Fix it or remove the project.

⚠ P0 — the site currently cannot build

Two files have stray comments appended (likely by the refactor-watcher agent): package.json ends with // Prettier formatting, making it invalid JSON — npm install and next build fail — and app/layout.tsx ends with an HTML comment <!-- Favicon update -->, which is a TSX syntax error. Also dead: aiProjectsData is defined but never rendered, and the dark-mode toggle state exists but no button uses it. Fix these before anything visual.

03

Visual system

The look that replaces gradients: one ground, one ink, one accent, strong type.

Color — dark, but disciplined

#101317 ground
#1A1E24 surface
#E9E7E2 ink
#8A8F98 muted
#4F8CFF accent
  • One accent, used sparingly: CTA buttons, links, the eyebrow labels. Never in body text or headings.
  • No gradient text. Headings are solid ink at heavy weight — that is what confidence looks like.
  • Keep dark mode as the default (it suits dev work) but colors must pass 4.5:1 contrast.

Type & motion

  • Keep Geist (already loaded) — but use it properly: 600–800 weight, −2% tracking for headlines; 400 at 16–18px for body.
  • Geist Mono for labels — eyebrows, tech tags, metadata. Gives the “engineer” texture without 3D.
  • Motion budget: fade+8px rise on scroll-in, 200ms, once. Button hover = color shift only. Delete: cursor, loading screen, magnetic buttons, parallax, orbs.
  • Performance target: LCP < 1.5s on 4G mobile. Removing Three.js from the critical path gets you most of the way.
04

Roadmap

In order. Each step is shippable on its own.

  • P0

    Fix the build

    Remove the stray comments from package.json and layout.tsx; delete dead aiProjectsData and the unused dark-mode state; disable whatever agent hook is appending junk to files. Verify npm run build passes.

  • P1

    Real screenshots + copy pass

    Capture screenshots of every live project (device frames for mobile). Rewrite hero and about copy: cut “enthusiastic/passionate,” lead with the store-published apps, fix Gama/Gamma, remove the broken-demo note. Rename categories. Add an OG image so shared links show a preview.

  • P2

    Restructure into the layout above

    4 case studies + compact project table, process section replacing services, proof strip, skills as a plain list. Strip Three.js, the loading screen, and the custom cursor.

  • P3

    Credibility layer

    Collect 2 testimonials, add outcome metrics to each case study, add a Calendly/WhatsApp path, sitemap + robots, and wire up the analytics util you already wrote.
